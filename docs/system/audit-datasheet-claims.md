## The seven claims

| # | Claim | Verdict | Source + quote | Consequence for the pod |
|---|---|---|---|---|
| 1 | TS/MR = NTC + button input. EN_PUSH default, TS < ~90 mV for ~10 s on battery = ship mode (dead until dock/button wake) | **CONFIRMED**, with two corrections | [BQ] p.9 §7.5: VTSMR "TSMR voltage to detect a button press event, battery only mode" max 90 mV; tLPRESS MR_LPRESS=01 = 9/10/11 s. p.36: MR_LPRESS reset 2b01 = 10 s. p.37 SHIP_RST reset 0x11: PB_LPRESS_ACTION 2b10 "Enable shipmode"; EN_PUSH 1b1 "Enable Push Button and Reset Function **on Battery Only**". p.21 §8.3.8: pulsed 60 µA source runs "as long as it is enabled by the EN_PUSH bit". Wake: "push button has to be low for tshipwake" (2 s, p.10) or VIN > UVLO. **Correction A** (p.22 Fig 8-5): after tLPRESS the part is "Ready to Enter Shipmode"; SYS drops when "TS/MR is high" again, i.e. the pod dies on release, not at 10 s. **Correction B** (p.26 Table 8-6): "Pushbutton input: Charge/Adapter **Yes**, Battery 'Yes, if enabled', Ship Yes, Shutdown No". EN_PUSH only gates the battery-only case. p.22 §8.3.11: a ship request can wait "except adapter removal" | The sub-power register plan "EN_PUSH = 0 removes the paths" is incomplete. Docked, TS < 90 mV for 10 s (adapter bias 38 µA: NTC > ~68 °C, or a J8-J9 bridge with the LED on) still arms ship mode, which fires at undock (pod dead). **Also write PB_LPRESS_ACTION = 00 (do nothing)** (p.37), not only EN_PUSH = 0. Before the plan is written (power-up, after any HW reset) the defaults apply. The ~84 °C figure is right (1.49 kΩ x 60 µA = 89 mV, B3435). Only dock (VIN) wakes the pod: SW1 is on PA0, not TS/MR |
| 2 | In ROM DFU PA2 (USART2_TX) drives TS high; charger reads "cold", pauses charging | **CONFIRMED** (mechanism); level during USB DFU not stated by ST | [AN2606] Table 199, p.466: "USART2 ... PA3 pin: USART2 in reception mode. Used in alternate push-pull, pull-up mode. **PA2 pin: USART2 in transmission mode. Used in alternate push-pull, pull-up mode.**" Fig 118, p.470: on USB detect "Disable all interrupt sources and other interfaces clocks". [BQ] p.23 §8.3.13.1: "Charging and safety timers are suspended when VTS < VHOT or VTS > VCOLD"; floating TS clamps at 2.2/2.8/3.3 V (p.9) and sets TS_OPEN_STAT. [DS] p.238: weak pull-up 30/40/50 kΩ | Even if only the internal pull-up acts (computed, 10k NTC at 25 °C, 38 µA bias): TS = 0.82-1.03 V = "cool" (½ ICHG) to "cold" (> 1.0075 V, suspended). Push-pull high (3.0 V) is above the clamp: TS_OPEN + suspended. So **charge paused or halved for the whole DFU session**; no ship-mode risk (needs < 90 mV). The datasheet gives no clamp sink current for a 3.0 V push-pull source (abs max "all other pins" 5.5 V is met). Accept; or a series resistor PA2-TS would bound it (costs ADC accuracy). Full pin map vs this package in the table below |
| 3 | Watchdog option B HW-resets after ~160 s without I2C (40 s with setting 10); would power-cycle a long DFU unless disabled first | **CONFIRMED** | [BQ] p.19-20 §8.3.7.6: "The watchdog timer is enabled by default ... **Once the initial transaction is received, the watchdog timer is started.** The watchdog timer is reset by any transaction ... If the watchdog timer expires ... all charger parameters registers ... are reset to the default values." Table 8-4: 00 "only perform a software reset after 160s"; 01 "HW_Reset after 160s"; 10 "HW_Reset after 40s"; 11 "completely disabled". p.35 IC_CTRL reset 0x84: WATCHDOG_SEL **2b00 (default)**. p.22 §8.3.10 HW reset: battery FET off, "Engage pulldown on SYS", Autowake timer (p.36, default 1 s), "Reset all registers to default". p.38 SYS_REG: WATCHDOG_15S_ENABLE reset 0 = "HW reset after 15s if no I2C transaction after VIN plugged" | The docs are right. Real defaults: 160 s, **register revert only (no power cycle)**, armed only after the first I2C access. Option B (01) = SYS dead ~1 s + all registers default (ICHG 10 mA, TS_HOT 60 °C, EN_PUSH 1), so a DFU running or idle > 160 s since the last I2C access is killed; the stub must write 11 first, as planned. Also: B fires **in Off/Stop 2** unless the MCU wakes (RTC) < 160 s, otherwise the "Off" pod reboots by itself. Datasheet is self-inconsistent: §8.3.9 (p.22) says "normal 50-second watchdog"; Table 8-4/tWDOG (p.10) say 160/40 s. Bench-read the registers |
| 4 | ILIM default 500 mA; charge current default 170 mA after docking; CC-less USB-A on unenumerated port = 100 mA | **PARTLY: ILIM right, "170 mA default" WRONG** | [BQ] p.36 TMR_ILIM reset 0x4D: ILIM_2:0 "3b101 = 500mA(max.)"; p.7: ILIM=500 mA gives 450/475/498 mA; p.18 §8.3.6: "The ILIM settings of 100mA and 500mA are designed to be the maximum value to support standard systems." **ICHG_CTRL (p.32) reset 0x05**: "For ICHG <= 35mA = ICHGCODE +5mA" = **10 mA**. 170 mA = code 44, written by firmware. **CHARGECTRL0 (p.33) reset 0x2C: VINDPM_1:0 = 2b11 "Disabled"** (options 4.2/4.5/4.7 V). USB 2.0 100 mA unconfigured: standard, not re-opened | Risk 10's "170 mA charge from docking" is firmware, not hardware: the real power-up state is ILIM 500 mA + ICHG 10 mA = ~20-25 mA input, safe on any port (sub-power's own Key numbers table already says 10 mA). Hazard starts only when firmware writes 170 mA with ILIM left at 500 mA. Plan: ILIM = 100 mA setting (80-98 mA, p.7) until enumeration/CC advert, ICHG <= ILIM - system load (~8 mA). **Also set VINDPM = 4.2 V**: default is off, so nothing backs charging off when a weak port's VBUS collapses (VBUS at the pin is ~4.7 V after D4; 4.5 V leaves only ~0.2 V) |
| 5 | PB4 NJTRST reset function with internal pull-up back-feeds the unpowered mic (supply = PA5) in reset/ROM DFU/Off; PB3 too if driven while PA5 low | **CONFIRMED** (PB3 only if driven: it is floating at reset) | [DS] Table 26 note 5, p.130: "After reset, this pin is configured as JTAG/SWD alternate functions. The internal pull-up on PA15, PA13, **PB4** pins and the internal pull-down on PA14 pin are activated." [RM] §13.3.1 p.624: "**PB4: NJTRST in pull-up**; **PB3: JTDO/TRACESWO in floating state no pull-up/pull-down**". p.633 GPIOB_MODER reset 0xFFFF FEBF (PB3, PB4 = AF); p.635 GPIOB_PUPDR reset 0x0000 0100 (PB4 = PU). p.416: "In Stop 2 mode, all I/O pins keep the same state as in Run mode". [AN2606] Table 199 never touches PB3/PB4. Mic: abs max DATA/CLOCK "-0.3, +5.0 V", input current "±5 mA", "Powered Down Mode (mic off)" is a valid state | Pull-up is 30-50 kΩ to 3.0 V: ~(3.0 - 0.6)/40k = ~60 µA into the mic, not damage (no VDD+0.3 V rule, < 5 mA). In reset and ROM DFU it is unavoidable but harmless (docked). **In Off it is firmware-fixable and matters: ~60 µA against a 16.5-24 µA Off budget.** Firmware must set PB4 to analog/no-pull before Stop 2 (state is retained). SWD is unaffected; ES0499 §2.2.20: only full 5-wire JTAG breaks if PB4 is repurposed |
| 6 | VDDUSB >= 3.0 V (datasheet) but AN2606 requires 3.3 V; 3.0 V rail marginal for DFU | **PARTLY: both quotes exist, but the conclusion overstates it** | [DS] Table 32 p.156: VDDUSB "USB used" **3.0-3.6 V**. Table 150 p.304: VDDUSB 3.0-3.6 V, **footnote 1: "USB functionality is ensured down to 2.7 V, but some USB electrical characteristics are degraded in 2.7 to 3.0 V range."** [AN2606] Table 199 p.469: "Note: VDDUSB IO must be connected to 3.3 V as USB peripheral is used by the bootloader." The same note appears 21 times across families: boilerplate, no tolerance, no bootloader-specific limit. [AN5373] p.3: on small packages "VDDUSB ... internally bonded to a VDD pin"; [DS] Fig 9 p.92: UFQFPN48_SMPS has no VDDUSB pin | 2.955 V (-1.5 %) is 45 mV under the 3.0 V "USB used" minimum but inside the 2.7 V functional guarantee. **Do not raise the LDO on the strength of AN2606** (risk 9's "raising it for DFU" is not required by any document). Keep sub-dock-usb issue 6(A): bench-test enumeration and a full DFU at 2.95 V, since "some USB electrical characteristics are degraded" is unquantified. DFU runs docked (VSYS 4.5 V, no bridge peaks on +3V0) |
| 7 | U3 ~0.2 W at 1C, ~+21 °C die rise; RθJA etc.; does a linear charger from 5 V at 175 mA dissipate that | **PARTLY: thermal constants right, power understated, "heat lever" wrong** | [BQ] p.5 §7.3: RθJA "EVM(2)" 65 °C/W, "JEDEC(1)" 107.1 °C/W, RθJB 30.3; fn (2) "1oz Copper, 2-layer board". p.20 §8.3.7.7: "PDISS = PSYS + PBAT; PSYS = (VIN - VSYS) * IIN; PBAT = (VSYS - VBAT) * IBAT; TJ = TA + θJA * PDISS ... θJA is largely driven by board layout." p.33: THERM_REG default 100 °C | Doc's number = (4.5-3.3) x 0.17 = 0.204 W x 107.1 = +21.8 °C: right arithmetic, **but only PBAT at VBAT = 3.3 V**. Datasheet formula, VIN pin 4.7 V (5 V - D4 ~0.3 V, unmeasured), ISYS 9 mA, ICHG 170 mA: **0.29 W @3.0 V, 0.24 @3.3, 0.17 @3.7, 0.12 @4.0, 0.09 @4.2** = +19...+6 °C (65 °C/W) or **+31...+9 °C (107 °C/W)**. With a bare 5.0 V VIN it is 0.35 W at 3.0 V. So 0.2 W is a mid-charge figure; design R23/RT1 on **~0.3 W** (CC start, a few minutes from a low cell). Neither θJA is this board (34x13 mm, sealed, over a pouch). **SYS_REG battery tracking does not cool U3**: total = (VIN - VBAT) x IBAT + (VIN - VSYS) x ISYS; VSYS only moves the small ISYS term (computed: < 0.01 W change); it relieves U4, not U3. Real levers: lower ICHG while VBAT < ~3.5 V, move RT1/J9, or add dissipation outside U3 |

## Pins the ROM bootloader configures on this package (AN2606 Rev 69 Table 199, pp.466-469, vs UFQFPN48_SMPS and the pod nets)
DS Fig 9 p.92: this package has PA0-PA15, PB0, PB1, PB3-PB8, PB13-PB15, PC13-15, PH0/1/3. It has **no** PB2, PB9-PB12, PC0/PC1, PC10/PC11, PG*, so I2C2, I2C3, USART3, SPI3 (except PB5), SPI2_NSS and FDCAN1_TX are not bonded out.

| Bootloader function (AN2606 text) | Pin | Pod net | Effect in ROM DFU |
|---|---|---|---|
| USART2_TX "alternate push-pull, pull-up", output | PA2 | TS | **charge paused/halved** (claim 2) |
| USART2_RX input, pull-up | PA3 | CC_SENSE | pull-up on CC via R19 (10k): CC ~0.65 V vs 80 µA Rp (derived); VBUS is already on, harmless |
| USART1_TX "alternate push-pull, pull-up", output | PA9 | GB_P (Q2 P gate) | high = P-FET off: safe |
| USART1_RX input, pull-up | PA10 | R11 (100k pull-up) | the bootloader already enables a pull-up: **R11 is redundant** (supports ECR-0003) |
| I2C1 SCL/SDA open-drain pull-up | PB6 / PB7 | NC / LED_K | LED stays off (cathode high) |
| SPI1 MOSI/MISO/SCK/NSS, push-pull pull-down | PA7 / PA6 / PA5 / PA4 | GA_N / I_SENSE / MIC_VDD / VBAT_SENSE | N gate off (safe); MIC_VDD pulled low (mic off); PA6 via R22 1k, PA4 reads ~0.14 V: all harmless |
| SPI2 SCK/MISO pull-down | PB13 / PB14 | I2C_SCL / I2C_SDA | idle ~2.1-2.5 V against the 10k pull-ups; no I2C in DFU, harmless |
| USB DM/DP "input no pull" | PA11 / PA12 | USB_DM / USB_DP | as designed |
| SPI3_MOSI pull-down, FDCAN1_RX pull-up, SPI2_MOSI pull-down | PB5 / PB8 / PB15 | NC | none |
Bridge in ROM DFU: PA8 and PB0 are analog (R3 pulls P gate high, R6 pulls N gate low), PA7 pulled low, PA9 high: **all four FETs off.**

## Net effect on the risk list
- Risk 4: right in substance; add PB_LPRESS_ACTION = 00; ship fires on release; docked path exists.
- Risk 5: right; defaults are register-revert only; option B also bites in Off.
- Risk 9: AN2606's 3.3 V is boilerplate; DS says functional to 2.7 V; no LDO change implied.
- Risk 10: "170 mA from docking" is a firmware value; power-up is 10 mA; add VINDPM and ILIM 100 mA until enumeration.
- Risk 11: right; cost is Off-mode µA and partial mic power, not damage.
- Risk 13: 0.2 W / +21 °C is the mid-charge point; plan on ~0.3 W; tracking mode is not a U3 lever.
